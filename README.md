# 悬壶 · 临床病房模拟

在一间最多容纳四位患者的病房里值班。你可以查看体征、开检查、给药和实施处置，再从监护仪和化验结果中观察病情变化。切换床位后，其余患者的病程仍会推进。

## 开始游戏

电脑上可以直接打开 `web/index.html`，它需要同目录中的 JavaScript 文件。也可以在仓库根目录启动本地网页服务，再访问 [本地游戏](http://localhost:8000/)。

```sh
python -m http.server 8000 --directory web
```

进入病房大厅后选择床位，或点「接诊新患者」。点击人体图上的器官可以查看对应指标。遇到陌生病例时，可使用上级医师提示和行医手册。进度保存在当前浏览器，续玩时请使用同一浏览器和入口。

在病房底部的「菜单」里可以管理存档：

- **重新开始本病例**会重置当前患者的处置和病程。
- **强制移除当前患者（测试用）**会直接腾出这张床，跳过结局统计、病历、手册和成就。移除最后一位患者后，大厅保持空床，可重新接诊。
- **重置游戏存档**需要再次确认，会清空本游戏的所有床位、历史记录和设置。大厅也有同名入口。

## 病房与监护

- 在床旁「菜单 → 查看操作日志」可回看本床给药、处置和检查回报，最近记录在前。第 6 级只显示床旁已公开的资料。
- 「菜单 → 当前输液与泵药」显示定时输注的已输量、剩余时间，以及持续泵的当前速率。点进单笔医嘱可提前结束输注或停泵，日志记录停止时间。固定总量输注沿用开单计价，持续泵的费用累计到停泵时。只记录了给药量的静滴和输血医嘱列在「近期输注相关记录」，并注明时长未记录。
- 点击姓名旁的「病例说明」查看当前床位的入院记录。主诉、现病史、既往史、用药史和过敏史分别记录，各条病史注明来源与取得时间。在「检查 → 问诊与院前资料」中可询问本人、家属、目击者，或调阅急救交接和既往资料。昏迷或插管可能使本人暂时无法回答，恢复交流后可补问。
- 1–5 级的入院交接逐渐简略。第 6 级「急诊首诊」沿用同种子 5 级患者和病情进程，开局仅提供来诊线索和首测。查体发现与化验按获取时间进入病历和报告，例如在床旁快速检查中测指尖血糖，再复测观察变化。
- 血常规和动脉血气按开单时采样。高血糖病例可从「快速床旁检查」查定性血酮，在「定向化验」复核有效渗透压。留置导尿后，可在床旁记录尿流率。高血压急症在 1–5 级可从出院评估直达心脏面板。第 6 级在「床旁查体 → 循环与末梢灌注」取得血管收缩驱动评估，心脏面板保留上次测量时间与游戏目标。
- 孕 34 周的重度子痫前期病例可在「操作」中查看分娩评估。确认后按模拟时钟推进 10 分钟，暂停时保留进度。产后观察从胎盘娩出开始计时，可在产科进程中回看分娩时的母体体征和新生儿交接记录。
- 点「给药」可展开「常用」「急救」或按临床用途找药，也可直接搜索通用名和已收录的商品名。打开药品再返回，会保留刚才的分组和搜索词。尼卡地平采用持续泵入，可调速或停泵；左乙拉西坦按总量定时静滴，可从床旁意识与抽搐评估复查反应。
- 药物标价使用人民币模拟参考价。普通给药和固定总量输注按所开总量计费，持续泵按实际泵速和模拟运行时间累计。医保模式在给药前显示预计新增自付，费用明细和结算页保留药费（含血液制品）、医保支付与家庭自付。旧存档沿用原总额，药费明细从更新后开始记录。
- 胰岛素的「泵入」按固定总量开单。给药页和日志显示实际总量与输注时长，输注结束后仍可观察后续药效。
- 去甲肾上腺素、多巴酚丁胺、异丙肾上腺素和血管加压素按设定速率持续静脉泵入。再次打开同一床的药品可查看当前泵速、调速或停泵。撤除全部循环支持后，游戏要求窦性心律、收缩压 ≥90 mmHg、平均动脉压 ≥65 mmHg 连续维持 15 个模拟分钟。出院评估显示剩余时间。
- 「报告」汇总本床查体发现、内镜止血记录、待回报项目与历次检查。打开时可接收新结果，展开复查报告可对照前后两次采样。结算后的接诊病历保留陈述来源、病史时间、已询但未取得的资料和首测体征。
- 急性肾损伤病例需连续观察自身尿量和肌酐趋势 30 个模拟分钟。接受血液透析后，观察从透析结束重新开始。床旁可复核导尿与尿量，并在「报告」中对照历次「电解质+肾功」的肌酐结果。
- 出院入口位于床旁「菜单」第一项。1–5 级使用普通出院时，符合条件的病例在同一菜单提供「稳定期留观快进」，可推进最多 6 个模拟小时。到达观察目标、有检查回报或出现重症时自动结束。
- 顶部「等病情变化」可用于任何病例。任一床出现明显改善或恶化、危急情况、检查回报、到达复评时间或新达出院条件时，全病房恢复 1× 计时。生命体征面板会显示床号、等待时长和原因，事件也会写入相应床位的日志。最长等待 6 个模拟小时。手动结束等待也会恢复 1×；需要停表时，点倍速左侧的「暂停」，再点「继续」恢复。
- 血糖尚未达标时，可在「胰腺 → 等待血糖变化」推进全病房。进入本病例目标范围、血糖向异常方向再变化 2 mmol/L、遇危情或检查回报，都会恢复 1×；最长等 30 个模拟分钟。复评前后的读数和结束原因写入本床日志。
- 生理引擎根据出血、气道阻力、循环和代谢等因素推演病情。同一种处置在不同患者身上可以产生不同结果。
- 病例涵盖电解质紊乱、中毒、感染及创伤等场景。出血按部位记录，机械通气患者可进行自主呼吸评估和撤机。诊疗记录、趋势图和会诊分享码可用于复盘。
- 选中心脏可查看最近 4 秒的单导联心电图。床旁的心搏音随 R 峰触发，游戏快进时仍按实时心率播放。静音不影响波形。
- 大厅及从大厅打开的工具页只播放高优先级报警。各床位独立报警，室颤响三短声，心静止响较轻的持续音。音量默认 20%，可调节或静音。
- 物理降温和被动保暖位于「操作 → 体温处置」。环境冷热、运动和睡眠仍在菜单的「环境 / 场景」中。
- 在肺面板或「操作」可打开本床的流量计，拖动后点「应用流量」。自主呼吸时调供氧流量，游戏根据呼吸需求估算吸入氧浓度。插管后调呼吸机吸气流量，送气不足时会影响潮气量和通气；达到目标潮气量后，提高流量会缩短送气时间。肺面板和血气报告分别保留当前和采样时的分压读数。
- 大厅或床旁菜单的「现实模式」提供「医保与自付」「真实出院」「禁用暂停」三个独立开关，即时应用到全病房。「禁用暂停」默认关闭。在已暂停的病房开启后，全部床位恢复 1× 计时，仍可调整倍速或等待病情变化。旧版已开启现实模式的玩家沿用医保规则。
- 开启「真实出院」后，点击「菜单 → 办理出院」可取消或确认签字。签字前可使用床旁查体、监护和检查报告判断病情。签字时全部达标按原规则结算，一般问题扣分出院，仍有重大问题则判定本例失败。
- 结算页和「病历档案」保存本例启用的现实规则、签字时的判定理由、加扣分明细及可滚动的操作日志。

## 技术要点

### 机制驱动而非规则驱动

```js
// ❌ 规则驱动：同一个操作在任何病情下结果一样
if (给了胰岛素) 血钾 -= 1.2;

// ✅ 机制驱动：模块只写驱动，引擎统一推导
S.svrDrive = Math.min(16, (S.svrDrive || 8) + 0.012 * dtMin);
const toneTarget = clamp(17.5 * baro * (0.45 + 0.55 * reserve) * pressorGain
    - (S.infection || 0) * 11.0
    + (S.svrDrive || 0)
    + clamp(((S.icp || 0) - 0.60) * 45, 0, 18), 4, 42);
```

### 氧合：分流方程

```js
const arterialContent = (1 - shunt) * capillaryContent + shunt * venousContent;
```

模型按肺内分流比例混合血液中的氧含量，计入血红蛋白结合氧和溶解氧。血气的 PaO₂ 和监护的饱和度从同一份动脉血推导。吸氧可以提高通气肺区的氧分压，严重分流时动脉血氧仍可能偏低。

### 出血按部位记账

```js
// 每个出血点独立计速率，止血只影响对应部位
S.bleedingSites[site] = rate;
S.bleedRate = Object.values(S.bleedingSites).reduce((a, b) => a + b, 0);
```

## 构建与发布

在仓库根目录使用 Python 3.8 或更高版本。网页构建只使用 Python 标准库。版本编号、更新记录和网页同步流程见 [仓库维护约定](AGENTS.md)。

| 用途 | 命令 | 结果 |
| --- | --- | --- |
| 发送给玩家离线游玩 | `python tools/build_singlefile.py` | `dist/xuanhu-single.html`，可单独打开 |
| 部署静态网站 | `python tools/build_site.py` | 将 `dist/部署包/` 的内容放到站点目录 |
| 上传网站压缩包 | `python tools/build_site_zip.py` | `dist/悬壶-网站包.zip`，解压后根目录即为站点入口 |

网站首页直接进入游戏，`download.html` 提供下载，`privacy.html` 展示隐私政策，`version.json` 列出本次构建包含的产物。

### Android APK

原版的发布脚本引用过 `app/android/`。公开仓库缺少 Android 工程、Gradle Wrapper 和 Capacitor 配置，因此从这份源码可直接构建网页版和离线 HTML；复现原版 APK 需要原作者的 Android 封装工程。发布同一应用的更新还需要沿用原有的签名流程。

如果已有与本次网页版本匹配的 APK，将它放在 `dist/` 后运行 `python tools/build_site_zip.py`。脚本会取最近修改的 `.apk`，以 `xuanhu.apk` 加入站点和网站 ZIP。没有 APK 时，下载页只提供网页和离线版入口。

## 源码与文档

游戏源码在 `prototype/`，页面入口是 `ui-v4.html`。`web/` 是可直接打开的同步副本。修改源码后，按顺序运行以下两条命令更新并核对网页版。

```sh
python tools/build_site.py --sync-web
python tools/build_site.py --check-web
```

开发者从 Git 克隆仓库后，可用 Node.js 20 或更高版本运行 `npm test` 验证生理引擎、病例和心电时序。`npm ci` 后运行 `npm run test:browser` 可在浏览器复核问诊、报告复查、双床禁用暂停、出院和归档；可以使用本机 Edge 或通过 `BROWSER_EXECUTABLE` 指定 Chromium 浏览器。发布用的源码 ZIP 和网站包仅包含运行与构建所需的内容及配套文档。

`tools/` 也包含独立的软著材料生成工具，`docs/` 保存玩法、模型设计及历次版本资料。模型设计和数据处理说明见[技术剖析](docs/技术剖析.md)和[隐私政策](docs/隐私政策.md)。

> **关于测试脚本的保留说明**
>
> `tools/` 下的脚本不参与游戏运行，打包时也不会进入 APK、网页包或离线 HTML，
> 对游玩没有任何影响。保留它们是为了在修改生理引擎后能快速回归，
> 避免「改了 A 坏了 B」。只想发布的话可以整目录删除。
> 按 `.gitattributes`，发布归档（`git archive`）会自动排除这些脚本。
>
> 浏览器端测试需要先 `npm install`（仅 `playwright-core`）。

本作为医学教学模拟，建议 16 岁以上玩家使用。病例、数值及处置效果仅供模拟学习，请勿用于真实诊疗。代码采用 [MIT 许可证](LICENSE)。
